## Goal
Make a C-1-type silent row loss impossible to commit unnoticed, and make every dataset's code provenance
identifiable. This brief does **not** repair or replace any canonical data (no authorization; D-16, D-17).

## Inputs
- `docs/devlog/2026-10-28-m2-decision-recommendations.md` §4–§5 (C-1 diagnosis: not reproducible with any
  committed parser; leading hypothesis a transient fault during the 2026-10-24 import; the manifest records no
  code state).
- The O-2 report (`evidence/owner_checks/o2_canonical_rows_20261028T014419Z.*`).
- Code: `src/tsclaude/marketdata/archive/importer.py` (`_parse_file`, `_commit`, manifest `tool`),
  `marketdata/archive/csvparse.py`, `store/lake.py` (`verify`), `store/lake_admin.py`.

## Deliverables
1. **Code provenance in every new manifest:**
   - `tool` extended with `git_commit`, a `git_dirty` flag (tracked files), and `python` and key library
     versions;
   - unknown provenance is recorded as `null`, never guessed;
   - lake format version bump if the manifest schema changes.
2. **Independent row count:**
   - after parsing a verified archive, count its data lines independently (a byte-level newline count of lines
     starting with a digit, excluding a known header);
   - require `parsed rows + malformed + rejected == data lines`;
   - otherwise **fail the import** (fail closed) with both numbers in the error, before anything is staged.
3. **Post-write verification:** before commit, re-read every written Parquet part, check its row count and
   content hash against the staged part info, and abort the commit on any difference.
4. **Import log:** a JSON line per import under `evidence/imports/_log/` (request, code provenance, per-file
   counts, outcome). It is append-only and never overwritten.
5. **Documentation:** devlog, metrics row, and an update to the AP-1 owner procedure describing the new failure
   modes.

## Acceptance tests
- **Lost row:** a synthetic archive where the parser is patched to drop one row makes the import fail. Nothing
  is staged or committed, and the error names the file and both counts.
- **Malformed rows:** an archive with a malformed row passes, and the count identity holds.
- **Manifest provenance:** the manifest contains the commit and the dirty flag, and `null` when git is
  unavailable.
- **Corrupted part:** corrupting a written part between write and commit (test hook) aborts the commit.
- **Regression:** AP-1 bounded-memory and existing importer, QA and verify tests pass. Re-importing B01 (fixture
  scale) still gives the same dataset id when the content is unchanged.
- **No performance cliff:** the line count is streamed and memory stays bounded per month.

## Constraints
- No change to existing datasets, the canonical lake, the holdout or `contracts/`.
- The C-1 parity batches (O-5) and any repair (E-5, D-17) are separate, later approvals.
