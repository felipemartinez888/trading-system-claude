# Task brief M1-T2 — Wire live market data into the app and dashboard

- **Owner role:** Platform & UI Engineer (`platform-ui-engineer`)
- **Milestone:** M1 Live tape
- **Branch:** `task/m1-t2`

## Goal
Start/Stop in the dashboard really starts and stops Binance monitoring. The Markets and Health pages
show real data from `MarketDataService` with correct provenance. In-app notifications show health
events. A clearly labeled **demo detector** emits `WATCH` events end-to-end into a Signals inbox, so
the whole live path (bar close → detector → event → UI) is exercised before real strategies exist.

## Inputs (read, do not modify)
`CLAUDE.md`, `docs/DASHBOARD.md`, `docs/DATA_ARCHITECTURE.md`, `docs/DECISIONS_PENDING.md`
(L-01, L-02), `src/tsclaude/marketdata/service.py` (facade: `start(session_id=...)`, `stop()`,
`snapshot()`, subscriptions — re-subscribe after every restart), `src/tsclaude/contracts/*`,
the existing `src/tsclaude/api/*` and `frontend/` from M0-T4.

## Deliverables
1. **Supervisor wiring** (`src/tsclaude/runtime/supervisor.py` + API context): monitoring start →
   `MarketDataService.start(session_id=…)` with `configs/universe.yaml` and
   `configs/data_quality.yaml`; monitoring stop and app shutdown → `stop()`. Failures to start are
   surfaced (monitoring stays STOPPED with the reason), never shown as running. Event-store writes
   from the data layer go through the existing single store.
2. **API:** `GET /api/markets` (per market+symbol: latest closed bar, partial candle, best bid/ask,
   mark price, funding, freshness — all `Sourced` exactly as the service provides; no re-labelling
   in the API), `GET /api/health/streams` (stream states, last message age, reconnects, recycles,
   crashes, malformed counts, clock offset, REST weight usage, open gaps), `GET /api/gaps`,
   `GET /api/bars?market=&symbol=&interval=1m&from=&to=` (stored 1m bars with source), and
   `GET /api/signals` (demo WATCH events, see 4). Push snapshot deltas on `/ws/live` at most 1/s.
3. **Frontend:**
   - Markets page: watchlist table (spot and perp price, 24h change if computable from stored bars
     — otherwise `UNAVAILABLE` with reason, spread, funding, freshness dot) and a 1m candlestick
     chart per selected symbol using `lightweight-charts` (Apache-2.0; include the attribution it
     requires) with gap shading and source legend.
   - Status bar: real Spot / Futures stream status instead of the M0 `UNAVAILABLE` placeholders.
   - System › Health: stream table, gap list with resolution, clock offset, coverage timeline.
   - Notifications: in-app inbox + badge for stream state changes, gaps, crashes, demo WATCH events;
     optional local sound toggle (off by default).
   - Signals page: inbox listing demo WATCH events with a prominent `DEMO` badge.
4. **Demo detector** (`src/tsclaude/signals/demo.py`): on each closed 1m bar per symbol, emits a
   `SIGNAL_CREATED` event with stage `WATCH`, `run_mode=LIVE`, `strategy_id="demo_detector"`,
   `evidence_grade="X"` when |close/open − 1| exceeds a configurable threshold. Never `CONFIRMED`,
   never sized, never routed to any book. Every API field derived from it is `Provenance.DEMO`.
   Disabled automatically if any stream for that symbol is not HEALTHY (fail closed).
5. **M0-T4 review follow-ups:** (N1) Stop must stay available while the backend answers, even when
   values are STALE; (N2) on all platforms refuse static path segments ending in `.` or space,
   refuse Windows reserved device names, and compare `index.html` case-insensitively so it is always
   served with the injected token and CSP/no-store headers.
6. **Owner verification script** `scripts/verify_live.ps1` (and `.sh`): runs the app with
   monitoring auto-started for a given duration (default 2 h), then writes a JSON report to
   `evidence/live/` (stream uptime, reconnects, recycles, gaps detected/resolved/open, malformed
   count, bars per symbol vs expected minutes, clock offset stats). This is the M1 gate evidence.

## Tests

- A test that runs the real `MarketDataService` against the existing fake Binance servers from
  `tests/integration/marketdata/` through the API (start → bars appear → stop → STALE).
- Demo detector: never CONFIRMED, DEMO provenance, disabled on unhealthy streams.
- Frontend vitest: Markets table renders all provenance states; status bar reflects stream states;
  notification inbox.
- Static-path hardening tests for N2 (`/INDEX.HTML`, `/index.html.`, `/con`, `/assets/nul.js`).
